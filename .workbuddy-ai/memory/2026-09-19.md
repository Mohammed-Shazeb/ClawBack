## Restoring the e2e suite: app on cloud, tests on local

The two targets can coexist after all — but not the way I first assumed.

**`npx convex dev --env-file .env.test` still rewrites `.env.local`.** The flag
selects the *deployment*, it does not redirect where the CLI writes the resulting
URLs. So simply running it silently repoints the whole app at `127.0.0.1:3210`,
which is exactly what must not happen while the app is meant to be on cloud.

What works:

- `.env.test` holds `CONVEX_DEPLOYMENT=anonymous:anonymous-ClawBack` (the local
  backend, ports 3210/3211, still on disk at `.convex/local/default/`).
- `scripts/test-backend.mjs` (`npm run test:backend`) starts that backend **and
  guards `.env.local`**, putting it back the moment the CLI changes it.
- `verify-e2e.mjs` is unaffected either way: it defaults to `127.0.0.1:3210/3211`
  and never reads `.env.local`.

**The flaw worth remembering:** v1 of the wrapper restored `.env.local` in
`process.on("exit")`. That does nothing under a hard kill — `TaskStop`, a task
manager, or a supervisor sending SIGKILL skips every exit handler, so the app was
left pointing at a backend that was no longer running. Proved it by killing the
process and reading `.env.local` back: still `anonymous:anonymous-ClawBack`.

Fixed by making the file correct **during** the run rather than on the way out: a
400ms poll rewrites `.env.local` whenever it differs from the saved cloud values,
for the first 60s while `convex dev` settles. Exit handlers are kept only as a
best-effort extra.

**General lesson: never rely on cleanup-on-exit for state you must not lose.**
Any signal a supervisor can send bypasses it. Make the invariant hold while the
process runs.

Verified end to end: with the guard running, `verify:e2e` **264/264** and
`.env.local` stayed on `dev:charming-kudu-951`; after a hard kill it was still on
cloud, with the local backend gone. App routes `/`, `/cases`, `/cases/new` all 200.

`.env.local` was backed up to `$TEMP/.env.local.clawback.bak` before any of this
and restored twice — worth doing whenever a tool rewrites an env file.
