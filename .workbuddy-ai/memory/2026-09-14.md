## Bugs found and fixed

1. **CRITICAL — hand-fabricated codegen.** `convex/_generated/api.d.ts` at commit
   `4cfe100` contained an admitted manual edit. Regenerated with a real
   `npx convex dev`.
2. **CRITICAL — case status rewound.** `emails.ts` `applyExtraction` set
   `status: "ANALYZING"` unconditionally, dragging an `EVIDENCE_FOUND` case
   backwards on a revised statement. Fixed with `PRE_ANALYSIS_STATUSES` guard.
3. **CRITICAL — research duplication.** Two live passes could both store. Fixed
   with a `researchRunId` token stamped at claim time and checked at store time.
4. **CRITICAL — duplicated timeline events.** Same token fix; one event per real pass.
5. **CRITICAL — Convex write-conflict stranded deductions.** `claimForResearch`,
   `claimForAssessment`, `storeResearchResults` and `storeAssessment` all read/wrote
   rows shared by sibling deductions (the `cases` doc, plus all `deductions` via
   `recalcDisputableTotal`). Convex exhausted its retries and aborted, leaving a
   deduction stuck at `PENDING`/`ASSESSING` **with no recorded error** and the UI
   showing a fake "checking sources…" state forever. The catch block contended too,
   so `failAssessment` could not even mark it failed. Fixed by making every write
   single-document and moving all shared-row writes into their own small,
   independently retryable mutations (`advanceCaseToEvidenceFound`,
   `refreshCaseDisputableTotal`, plus new `getDeductionContext` /
   `getAssessmentContext` queries).
6. **IMPORTANT — validator widened ids.** `validateAssessment` returned `string[]`
   and callers cast with `as Id<"sources">[]`. Now typed through as `Id<"sources">[]`.
7. **IMPORTANT — fabricated passage.** `storeResearchResults` fell back to the
   provider's `description` summary as `relevantText`. Removed; the UI says
   "No passage was retrieved" instead.

## Conventions worth remembering

- Local dev loop: `npx convex dev` (via `run_in_background`, it hot-reloads);
  `node scripts/mock-providers.mjs` (ports 4590/4591/4592); env pointed at mocks
  with `npx convex env set`. Note the var is `OPENAI_BASE_URL`, not
  `OPENAI_API_BASE_URL`.
- `npm run verify:e2e` needs unique message ids per run. The local deployment keeps
  its data, and inbound mail is idempotent on the provider message id, so hard-coded
  ids get swallowed as replays on the second run. The harness now scopes them with a
  `RUN` prefix.
- Convex function paths in the HTTP API use `module:function` (colon), not
  `module.function`.
- **Any mutation that reads or writes a row shared between concurrent siblings will
  abort and strand work.** Keep claims single-document; put shared-row bookkeeping in
  its own small mutation that runs once per item.

## Decisions worth remembering

- **Approval never sends.** `approveLetter` sets `letter.status = APPROVED` and leaves
  the case at `AWAITING_APPROVAL`; the UI states plainly that nothing was sent.
- **Approved letters are immutable.** Both edit and regeneration refuse once APPROVED;
  the only way forward is `startNewDraft`, which *archives* the approved letter
  (`archivedAt`) rather than deleting it, so the approval record stays honest.
- **One live letter per case.** `resolveLiveLetter` returns the newest non-archived
  row; regeneration updates that row and bumps `version` instead of inserting.
- **Model sees labels, never ids.** Sources are labelled `S1..Sn`; `storeGeneratedLetter`
  re-verifies every cited id belongs to the case, which is what makes cross-case
  citation impossible.
- **Snapshot the figures.** The letter stores `depositAmount` / `totalDeductions` /
  `potentiallyDisputableAmount` at generation time so later recomputation cannot
  silently change what an approved letter claims. OpenAI never computes the total.
- **Edit buffer keyed to stored id+version**, not synced by an effect — a
  `react-hooks/set-state-in-effect` error, and it also fights in-progress typing.

# Day 5 — AgentMail Outbound + Two-Way Case Communication

## Two CRITICAL defects fixed (both pre-existing, both found by audit/verification)

1. **A landlord reply would have destroyed the case's analysis.** Inbound mail was
   unconditionally treated as a deposit statement and run through extraction, and
   `applyExtraction` deletes and rewrites *every* deduction on the case — so the first
   reply would have wiped out the assessment the dispute was built from. Fixed by
   classifying inbound mail as `REPLY` vs `STATEMENT` **before** insert
   (`looksLikeReply` in `convex/emails.ts`), and never scheduling extraction for a
   reply. Reply identity, strongest signal first: case `threadId` → `In-Reply-To`/
   `References` naming a message we sent → a `SENT` letter existing. **Subject-line
   matching is never the primary mechanism.**
2. **A sent letter could be regenerated in place.** `startNewDraft` deliberately
   skipped `SENT` letters (`else if (letter.status !== "SENT")`), so after a dispute
   was delivered, "regenerate" rewrote the document the landlord already held. Now
   `startNewDraft` archives every non-archived letter, and `draftLetter` refuses both
   `APPROVED` and `SENT`. **Rule: a document that has left the building is immutable.**

## Architecture rule applied again: pure contract module + pipeline module

`convex/outbound.ts` imports `_generated/server` at runtime, so the offline harness
**cannot load it** — `.verify/convex/outbound.js` fails with
`Cannot find module './_generated/api'`. The fix that generalises: put the *policy* in
a module with only `import type` from `_generated` (erased at compile time), and keep
the pipeline separate. So `convex/send.ts` (pure: `sendIdempotencyKey`,
`isSendableEmail`, `validateSendRequest`, `decideSendClaim`, `STALE_SEND_CLAIM_MS`)
pairs with `convex/outbound.ts`, exactly like `letter.ts`/`letters.ts` and
`response.ts`/`responses.ts`. `tsconfig.verify.json` can list the pipeline modules for
type-checking, but nothing may *import* them from `verify-pipeline.ts`.

## Idempotency design (Step 5)

Key is `send:{letterId}:v{version}` — per **document revision**, not per attempt. A
double click, a retried action and a replayed webhook all converge on one row and one
delivered copy; a genuinely revised letter gets a new key and may be sent again.
`decideSendClaim` is the pure decision table: `SENT` → refuse; `SENDING` younger than
`STALE_SEND_CLAIM_MS` (10 min) → refuse; `SENDING` older or `FAILED` → **reuse the same
row**. Reusing the row means one outbound record per document, and a crashed action
can never block a case forever. AgentMail's `client_id` is unavailable on
`/inboxes/{id}/messages/send`, so idempotency is enforced by the caller.

## Other decisions

- **Send is renter-triggered only.** Approval makes a letter *sendable*; nothing sends
  as a consequence of generation or approval. The envelope recipient is
  `cases.landlordEmail` (renter-supplied), explicitly **not** the letter's salutation.
- `performSend` (action) does no database writes; `recordSendSuccess` /
  `recordSendFailure` (mutations) are the only outcome writers, so a crash mid-send
  leaves a recoverable `SENDING` claim, never a half-written `SENT`.
- **`acceptsDispute` must mean "concedes the dispute", not "offers money".** The
  original prompt said "agrees in whole or in part", which made "I can refund $150"
  set both `acceptsDispute` and `offersPartialReimbursement`, making the flags
  redundant. Money is recorded through `offersPartialReimbursement`/`offeredAmount`.
- Widened a weak guard: the legal-conclusion pattern was
  `/(?:is|are)\s+legally\s+(?:required|obligated|entitled)/`, which missed "Are **you**
  legally entitled". Now `/\blegally\s+(?:required|obligated|obliged|entitled|liable|bound)\b/`.

## Test-quality lesson (worth remembering)

Two e2e checks **passed for the wrong reason** and hid a real failure:
- `waitFor("the retry succeeds", …)` waited for "an outbound message is SENT", which
  the *original* dispute already satisfied — so it returned instantly and the letter
  was read before the retry ran. Fix: wait for the specific condition (no `FAILED`
  rows remain **and** two `SENT` rows exist).
- An assertion used `.includes("based on the available housing guidance")` against a
  body containing "Based on…" — case-sensitive, so it failed on a capital B. Prefer
  comparing the sent text to the approved letter body **exactly**; that is a stronger
  check anyway.
**Rule: when a `waitFor` predicate could already be true, it is not a wait.**

## Day 5 second-pass audit (adversarial re-read of the send/reply paths)

Re-read `outbound.ts` and `emails.ts` for the defect classes that had already bitten
earlier milestones. Two paths checked out clean, one hole found and fixed:

- **Clean:** `recordSendFailure` guards `if (email.sendStatus === "SENT") return null`,
  so a late failure from an earlier attempt cannot overwrite a newer success. The
  symmetric case (a late success after a newer failure) correctly *does* upgrade to
  SENT, because the mail did go out.
- **Clean, and deliberately so:** `looksLikeReply`'s last fallback ("a SENT letter
  exists for this case") makes classification very permissive — after a dispute is
  sent, *every* later inbound message is a reply. This is intentional and the
  asymmetry justifies it: a statement misread as a reply is still stored and shown,
  whereas a reply misread as a statement runs `applyExtraction` and destroys the
  case's analysis. Do not "tighten" this without preserving that asymmetry.
- **Hole found and fixed:** the stale-claim takeover was retried **silently**. That
  path is not a retry of an observed failure — the earlier attempt may have reached
  the provider and simply not reported back, so the landlord can receive two copies.
  `recordSendSuccess` prevents a double *record*, never a double *delivery*.
  Provider-side idempotency is unavailable (no `client_id` on
  `/inboxes/{id}/messages/send`), so this cannot be closed from our side. Fix:
  *record* it — the takeover writes a `SEND_ATTEMPT_ABANDONED` timeline event naming
  the risk, while a plain retry after a `FAILED` send is deliberately not flagged.
  Two e2e checks pin both halves. **Lesson: when a guarantee cannot be met, do not
  quietly narrow it — surface it, and correct any earlier claim that overstated it.**
